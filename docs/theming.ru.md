# Темизация

wmkit никогда ничего не стилизует по именам классов. Он пишет атрибуты `data-wm-*` и инлайн-геометрию, а тема — это просто CSS, который реагирует на эти атрибуты. В пакете шестнадцать тем; заменив их своими, вы снимаете все требования к CSS, какие есть у библиотеки.

```js
import '@surdeddd/wmkit/themes/glass.css'  // тёмная полупрозрачная, вид по умолчанию
import '@surdeddd/wmkit/themes/light.css'  // светлая полупрозрачная
```

| Файл | Вид |
| --- | --- |
| `glass.css` | тёмная полупрозрачная, по умолчанию |
| `light.css` | светлая полупрозрачная |
| `retro.css` | фаски в духе Win98, без размытия |
| `terminal.css` | моноширинный шрифт, люминофорный зелёный, квадратные кнопки |
| `paper.css` | тёплый почти белый, заголовки с засечками, смещённая тень цвета чернил |
| `neon.css` | глубокий индиго с пурпурным и голубым свечением |
| `aqua.css` | глянцевый тайтлбар в тонкую полоску, заголовок по центру |
| `frost.css` | бледное матовое стекло, сильное размытие, скруглённые углы |
| `candy.css` | пастельный градиент в тайтлбаре, сильные скругления, пружинистая анимация |
| `carbon.css` | плоская индустриальная тёмная, квадратные углы, синяя полоса фокуса |
| `brutalist.css` | чёрная рамка 2px, жёсткая смещённая тень, моноширинный шрифт капслоком |
| `blueprint.css` | тёмно-синяя чертёжная сетка, пунктирное превью снэпа |
| `amber.css` | янтарный ЭЛТ-монитор со строками развёртки и свечением |
| `noir.css` | чистые чёрно-белые волосяные линии |
| `forest.css` | тёмная оливковая с заголовками с засечками |
| `synth.css` | закатный градиент в тайтлбаре поверх глубокого фиолетового |

Все они соблюдают один контракт: цели указателя 24px у кнопок управления окном, блок `prefers-reduced-motion`, который убирает переходы, и блок `forced-colors`, который заменяет кнопки подписанными глифами.

## Отдельное окно

Тема одевает все окна. Когда одному окну нужно выглядеть иначе, дайте ему вариант: рабочий стол отражает его в `data-wm-variant`, а ваш CSS уже оттуда переопределяет токены.

```js
wm.open({ id: 'log', meta: { variant: 'ghost' } })
```

```css
[data-wm-window][data-wm-variant="ghost"] {
  --wm-shadow: none;
  opacity: 0.88;
}
```

По умолчанию вариант читается из `meta.variant`. Чтобы выводить его из чего-то другого, передайте `windowVariant` в `attachDesktop`:

```js
attachDesktop(wm, root, {
  windowVariant: (win) => (win.layer === 'modal' ? 'sheet' : null),
})
```

## Контракт атрибутов

### Пишете вы, читает библиотека

| Атрибут | На чём | Смысл |
| --- | --- | --- |
| `data-wm-drag` | любой потомок | ручка перетаскивания; двойной клик переключает разворот; правый клик или долгое нажатие вызывает `onTitlebarContextMenu` |
| `data-wm-title` | любой потомок, включая теневой корень | узел заголовка; его текст следует за состоянием, а связь через `aria-labelledby` ставится только из того же корня |
| `data-wm-content` | любой потомок | скроллируемая область контента (только для стилей) |
| `data-wm-controls` | любой потомок | группа кнопок управления (только для стилей) |
| `data-wm-close` | кнопка | закрывает, если `closable` |
| `data-wm-minimize` | кнопка | сворачивает, если `minimizable` |
| `data-wm-maximize` | кнопка | переключает разворот, если `maximizable` |

Кнопки управления работают через делегирование, поэтому могут быть вложены где угодно внутри окна.

### Пишет библиотека, читает ваш CSS

| Атрибут | На чём | Значения |
| --- | --- | --- |
| `data-wm-desktop` | элемент рабочего стола | присутствует |
| `data-wm-window` | элемент окна | id окна |
| `data-wm-stage` | окно | `normal`, `minimized`, `maximized`, `snapped` |
| `data-wm-layer` | окно | `normal`, `floating`, `modal` |
| `data-wm-workspace` | окно | индекс рабочего пространства |
| `data-wm-focused` | окно | присутствует на окне в фокусе |
| `data-wm-dragging` | окно | присутствует во время перетаскивания |
| `data-wm-resizing` | окно | направление: `n`, `se`, … |
| `data-wm-pinching` | окно | присутствует, пока два пальца меняют его размер |
| `data-wm-variant` | окно | имя варианта, если у окна он есть |
| `data-wm-flash` | окно | ставится, когда модалка блокирует взаимодействие; остаётся до следующего заблокированного взаимодействия или до отвязки окна. Анимация проигрывается один раз на каждую установку, а атрибут потом не снимается: снятие вернуло бы элемент во власть входной анимации темы и проиграло бы её заново. Стилизуйте вспышку анимацией, а не статичным правилом |
| `data-wm-resize` | вставленные ручки | направление |
| `data-wm-snap-preview` | вставленное превью | присутствует |
| `data-wm-announcer` | вставленный live-регион | присутствует |
| `hidden` | окно | свёрнуто или на другом рабочем пространстве |

Геометрия задаётся инлайн через `transform: translate3d()`, `width`, `height` и `z-index`. Не воюйте с ней через `left`/`top` в CSS — позиционируйте через менеджер.

## CSS-переменные

`glass.css` и `light.css` выставляют один и тот же набор на `[data-wm-desktop]`:

| Переменная | Для чего |
| --- | --- |
| `--wm-radius` | радиус скругления окна и тайтлбара |
| `--wm-bg`, `--wm-bg-focused` | фон окна |
| `--wm-border`, `--wm-border-focused` | рамка окна |
| `--wm-shadow`, `--wm-shadow-focused` | тень окна |
| `--wm-titlebar-bg` | заливка тайтлбара |
| `--wm-text`, `--wm-text-dim` | текст контента и второстепенный текст |
| `--wm-accent` | кольца фокуса, рамки и превью снэпа |
| `--wm-accent-ink` | акцент там, где его нужно *читать*, — см. ниже |
| `--wm-blur` | радиус фонового размытия |
| `--wm-transition` | плавность перемещения и ресайза |

### Почему акцентов два

`--wm-accent` подбирается так, чтобы звучать на фоне окна: яркая рамка, кольцо фокуса, превью снэпа. Тот же цвет в мелком тексте часто нечитаем — небесно-голубой у `frost` даёт 1.4:1 на собственной поверхности, а розовый у `candy` — 2.1:1, оба далеко ниже 4.5:1, которых WCAG AA требует от основного текста.

Поэтому каждая тема несёт ещё и `--wm-accent-ink`: тот же тон, сдвинутый в читаемую сторону, пока он не перешагнёт 4.5:1 на фоне окна этой темы. На тёмных темах они обычно совпадают. Красьте им текст, а `--wm-accent` оставьте для всего, что не читают:

```css
.my-value { color: var(--wm-accent-ink, var(--wm-accent)); }
.my-chip  { border-color: var(--wm-accent); }
```

Запасное значение важно: написанная вручную тема, которая старше этого токена, продолжает работать, просто теряет гарантию.

### У прозрачности есть предел

Тема с просвечивающим окном смешивается с тем, что лежит под ним. Раньше `frost` был белым на 48%: на светлой странице это яркое матовое стекло, а на тёмной — плоский средне-серый, и на средне-сером не читается ни один цвет текста, какой есть у светлой темы. Теперь встроенные полупрозрачные темы достаточно плотные, чтобы их поверхность узнавалась на любом рабочем столе; ощущение матового стекла создаёт размытие, а не альфа.

Если пишете свою полупрозрачную тему, проверьте её на тёмном фоне до релиза. `tests/e2e/theme-contrast.spec.ts` меряет отрендеренные пиксели демо под всеми шестнадцатью встроенными темами и падает ниже 4.5:1.

`retro.css` — другая визуальная система, она выставляет `--wm-face`, `--wm-face-light`, `--wm-face-dark`, `--wm-face-darker`, `--wm-title-active-a`, `--wm-title-active-b`, `--wm-title-inactive`, `--wm-title-text`, плюс общие `--wm-text`, `--wm-text-dim` и `--wm-accent`.

Подстроить встроенную тему можно локальным переопределением:

```css
[data-wm-desktop] {
  --wm-radius: 3px;
  --wm-accent: #d3ff4e;
  --wm-bg: rgba(12, 15, 19, 0.7);
  --wm-blur: 18px;
}
```

## Переключение тем на лету

Все файлы тем нацелены на `[data-wm-desktop]`, поэтому если импортировать две сразу, победит последняя. Чтобы переключать на живую, загружайте их как URL и меняйте `<link>`:

```js
import glassUrl from '@surdeddd/wmkit/themes/glass.css?url'
import lightUrl from '@surdeddd/wmkit/themes/light.css?url'
import retroUrl from '@surdeddd/wmkit/themes/retro.css?url'

const link = document.createElement('link')
link.rel = 'stylesheet'
document.head.append(link)

export function setTheme(name) {
  link.href = { glass: glassUrl, light: lightUrl, retro: retroUrl }[name]
  desktopEl.dataset.theme = name
}
```

Атрибут `data-theme` позволяет ограничить ваши переопределения одной темой, чтобы они не протекали в другие, — именно так это сделано в демо.

## Тема, вариант, скин

Три слоя, от самого широкого к самому узкому:

| слой | достаёт до | меняет |
| --- | --- | --- |
| тема | всех окон на рабочем столе | токены |
| вариант | одного окна | токены, через `data-wm-variant` |
| скин | одного окна | саму разметку |

Тема и вариант перекрашивают то, что уже есть. Скин это заменяет: другие элементы, другие кнопки, другой тайтлбар. Берите скин, когда у окна отличается *структура*, и вариант, когда отличаются только цвета.

```js
import { skin } from '@surdeddd/wmkit/chrome'

const desktop = attachDesktop(wm, root, {
  skins: {
    plain: skin({ template: PLAIN }),
    compact: skin({ template: COMPACT }),
  },
})

desktop.mountWindow('notes', 'plain')
wm.update('notes', { meta: { skin: 'compact' } })  // пересобирается на месте
```

## Темы в виде текста

Таблица стилей, загруженная в `document.head`, не достаёт внутрь теневого корня, поэтому скин, собранный с `shadow: true`, её никогда не видит. Для этого случая те же шестнадцать тем поставляются строками:

```js
import { themeNames, themeStyle } from '@surdeddd/wmkit/themes'

const dressed = skin({
  name: 'dressed',
  shadow: true,
  styles: themeStyle('carbon', { shadow: true }),
  template: '<section><header data-wm-drag><span data-wm-title>{{title}}</span></header><div data-wm-content></div></section>',
})
```

`{ shadow: true }` здесь не опционален, и причину стоит знать. Кастомные свойства наследуются через теневую границу, так что токены проникают внутрь сами, — но правила, которые их используют, записаны как `[data-wm-window] [data-wm-drag]`, а внутри теневого корня нет предка с `data-wm-window`: этот атрибут живёт на хосте, снаружи. Подключите обычный текст — и цвета будут определены, но ничего ими не покрашено.

Теневая версия — та же таблица стилей с другой привязкой: селектор окна становится `:host`, его уточнения — `:host([data-wm-focused])`, потомки теряют префикс, которому больше не могут соответствовать, а блок рабочего стола сводится к токенам, которые он определяет. Правила контента становятся `::slotted([data-wm-content])`, комбинаторы `>` сохраняются как `:host > x`, псевдоклассы уходят внутрь `:host(...)`, а правила, которые не могут сработать внутри теневого корня, отбрасываются. Всё это генерируется, а не переписывается в рантайме, — `themeCss` остаётся байт в байт идентичным файлам `.css`, а `themeShadowCss` лежит рядом.

Теневой скин носит тему в собственных `styles`, какую бы тему ни носил рабочий стол, поэтому переопределения на `[data-wm-desktop]` до него не доходят. Чтобы подстроить одно теневое окно, задайте токены на хосте окна — `[data-wm-window]` или `[data-wm-skin="<name>"]`; правило страницы на хосте побеждает токены `:host` из теневого корня.

`themeNames` — полный список в том же порядке, в каком темы лежат в папке. Обе версии получаются из `pnpm themes`; тест перегенерирует их и падает, если кто-то правит таблицу стилей, не перезапустив генератор.

Импорт этой точки входа стоит веса всех шестнадцати таблиц стилей, причём дважды, поэтому берите её, только когда нужен именно текст. Загрузить тему обычным путём, импортом `.css`, по-прежнему дешевле.


## Тема с нуля

Минимальная, но полная тема — это примерно тридцать строк. Структурных требований всего два: окно — блочный бокс с явной высотой, а свёрнутое окно перестаёт занимать место.

```css
[data-wm-desktop] {
  position: relative;
  overflow: hidden;
}

[data-wm-window] {
  display: flex;
  flex-direction: column;
  box-sizing: border-box;
  background: #14161c;
  color: #e7eaf0;
  border: 1px solid #2a2f3a;
  transition:
    transform 240ms cubic-bezier(0.32, 0.72, 0, 1),
    width 240ms cubic-bezier(0.32, 0.72, 0, 1),
    height 240ms cubic-bezier(0.32, 0.72, 0, 1);
}

[data-wm-window][hidden] {
  display: none;                 /* [hidden] проигрывает display:flex — повторите его */
}

[data-wm-window][data-wm-focused] {
  border-color: #5b6472;
}

[data-wm-window][data-wm-dragging],
[data-wm-window][data-wm-resizing] {
  transition: none;              /* никогда не анимируйте наперекор указателю */
  user-select: none;
}

[data-wm-window] [data-wm-drag] {
  flex-shrink: 0;
  cursor: default;
  user-select: none;
}

[data-wm-window] [data-wm-content] {
  flex: 1;
  overflow: auto;
}

[data-wm-snap-preview] {
  background: rgba(211, 255, 78, 0.18);
  border: 1.5px solid rgba(211, 255, 78, 0.55);
}

@media (prefers-reduced-motion: reduce) {
  [data-wm-window],
  [data-wm-snap-preview] {
    transition: none;
    animation: none;
  }
}
```

В четырёх правилах легко ошибиться:

1. **Для `[hidden]` нужно повторить `display: none`.** `display: flex` побеждает правило `[hidden]` из стилей браузера, и свёрнутое окно осталось бы видимым.
2. **Отключайте переходы во время перетаскивания.** Переход на `transform` во время перетаскивания заставляет окно отставать от курсора.
3. **Не ставьте `overflow: hidden` на само окно**, если только не хотите заодно обрезать ручки ресайза: они чуть выступают за border box.
4. **Никогда не пишите голое правило `section { }`** на окружающей странице. Если ваши окна — элементы `<section>`, оно их заденет; ровно такой баг уже однажды попал в релиз.

## Ручки ресайза

`createResizeHandles` вставляет восемь абсолютно позиционированных div с `data-wm-resize`. Они прозрачные, их размер задаёт `hitAreas`, и у каждой правильный `cursor`. Стилизуйте их, только если хотите видимые ручки:

```css
[data-wm-resize] { background: transparent; }
[data-wm-window][data-wm-focused] [data-wm-resize='se'] {
  background: linear-gradient(135deg, transparent 50%, #5b6472 50%);
}
```

Они скрываются автоматически, когда окно нельзя ресайзить, и когда его стадия — ни `normal`, ни `snapped`.

## Движение и доступность

Каждая встроенная тема отключает анимации при `prefers-reduced-motion: reduce`, а `flipToTarget`/`flipFromTarget` отказываются от них ещё и на уровне JS. Анимацию сворачивания целиком можно также выключить или перенастроить по времени из контроллера: `animation: false` или `animation: { duration, easing }`. Держите фокус видимым — библиотека ставит окну `tabindex="-1"` и фокусирует его, так что обводка `:focus-visible` на `[data-wm-window]` не помешает. Если перенастраиваете `--wm-text-dim`, проверьте контраст: им пишется текст неактивного тайтлбара, который всё равно должен читаться.

### Цели указателя

Кнопки управления окном маленькие нарочно, поэтому каждая тема увеличивает их хит-зону прозрачным псевдоэлементом, а не саму точку. В итоге каждая кнопка занимает не меньше 24×24 CSS-пикселей, и соседние цели никогда не перекрываются — именно этого требует WCAG 2.5.8. Если перестилизуете кнопки, соблюдайте обе половины этого уговора: уменьшайте точку сколько угодно, но перепроверьте inset псевдоэлемента и `gap` на `[data-wm-controls]`, чтобы цели оставались в 24px друг от друга.

### Высокий контраст Windows

При `forced-colors: active` платформа выбрасывает ваши цвета, и без дополнительной работы три «светофорные» кнопки превратились бы в три одинаковых круга. Каждая встроенная тема в этом режиме перерисовывает их как кнопки с рамкой и символами `✕`, `–` и `□`, перекрашивает рамку окна в `Canvas`/`CanvasText`, отмечает окно в фокусе цветом `Highlight` и превращает превью снэпа в сплошную обводку `Highlight`. Своя тема должна делать то же самое — одного цвета никогда не хватает, чтобы различать кнопки.
